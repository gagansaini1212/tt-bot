# Isolate customers with row-level security

The web app and the execution worker connect to PostgreSQL as roles that row-level security applies to, never as a superuser or the schema owner, and read or write customer data only inside a transaction scoped to one customer. Work that spans customers, such as reconciliation, lists customer IDs through a function that returns nothing else, then handles each customer in their own scope. We chose this over a narrowly privileged role that bypasses row-level security for worker scans, because a mistake in that role's queries could mix customers' data, whereas here the database enforces isolation on every query the apps run. The cost is a transaction per customer on each pass, which is small for the ten simulated customers the local build targets.
